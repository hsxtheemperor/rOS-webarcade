# rOS

rOS is a browser-hosted OS experiment. `biosapi.js` provides browser APIs and
starts the WebAssembly boot chain. The C bootloader and kernel sources live in
`src/`; generated Wasm binaries and the read-only WebFS1 image live on the
virtual disk under `vdisk/vdisk01/`.

## Build

Install Clang with a wasm32 target, GNU Make, and Python 3, then run:

```sh
make -f makefile
```

This creates:

- `vdisk/vdisk01/bin/wboot/boot.wasm`
- `vdisk/vdisk01/bin/wkernel/kernel.wasm`
- `vdisk/vdisk01/bin/wbash/bash.wasm`
- `vdisk/vdisk01/initrd/webfs1.img`

The initrd is generated by the C builder at `src/boot/initrd/mkwebfs.c` from the
actual vdisk payloads and remains the base image. A browser-backed writable VFS
layer overlays it so the shell can create, rename, delete, and modify files in
memory while the static image remains the initial seed state. `src/assets/boot.png`
is used as the boot splash.

## Run and develop

Start the live development server (it also builds missing or outdated Wasm):

```sh
make -f makefile dev
```

Open [http://localhost:8000/](http://localhost:8000/) and leave the server
running in that terminal. It watches every file recursively under
`vdisk/vdisk01/bin/`; after a change settles, the open page automatically
reloads and boots the updated Wasm.

When you edit C sources or initrd files, rebuild in a second terminal:

```sh
make -f makefile
```

The browser reloads when a generated binary changes. Stop the server with
Ctrl+C.

The kernel mounts the WebFS1 base image and starts the `proc0` terminal
process. The shell supports read/write file operations through the browser VFS
layer, including `mkdir`, `touch`, `rm`, `cp`, `mv`, `cat`, `echo`, `grep`,
`head`, `tail`, `wc`, `ls`, `lsblk`, `tree`, `pwd`, and `clear`. `ls` includes
the virtual disk and supports paths such as `vdisk01/bin/wbash`. `lsblk`
reports the current virtual disk size. `proc0` parses commands in the kernel;
command implementations under `src/bash/` are compiled separately into
`wbash/bash.wasm` and use the kernel's terminal and filesystem bridge.
